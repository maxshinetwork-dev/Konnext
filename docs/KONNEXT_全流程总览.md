## 二、阶段逐段拆解

### 阶段 0：售前立项

| 谁 | 干什么 | 系统里 |
|---|---|---|
| 售前 | 建项目、填地址/联系人/房屋/楼层/施工阶段 | `project` 主表 |
| 售前 | 记家庭成员（成人/老人/儿童/保姆/宠物…） | `household_member` |
| 售前 | 记参建方（设计师/Builder/电工/空调/地暖…） | `project_party` |
| 售前 | 记方案倾向（有线无线 + 协议 + 预算 + 有无 KNX/地暖） | `solution_option` |
| 售前 | 走七步流程，每步一个时间戳 | `project.step1~7_at` |
| 售前 | **填免责维保月数**（0~12，默认 3） | `project.free_warranty_months` |

**关键**：第六步签字 = **方案定版信号**。没有它，后面全部走不动。
**方案倾向里的 has_knx / has_floor_heating** 会决定 SM2 清单上要不要显示"带 KNX 线""带地暖线"。

---

### 阶段 1：签约 → S1 定金

| 谁 | 干什么 |
|---|---|
| 售前 | 填签约价 `contract_price` |
| 财务 | 发 S1 Invoice（10%）→ 收款 → 点结清 |

**字段级所有权**：定金只有财务能写，售前只读。

---

### 阶段 2：SM1~SM4（现场会议）

四场会**顺序硬卡**：SM(n) 要完成，SM(n-1) 必须已完成**或**已标不适用。

> **老项目怎么办**：`na_flag` 标"不适用" + 填原因 → 后续 SM 可开。
> 这是顺序硬卡的**正规后门**——不取消卡点，但走一次记一次。

**每场 SM 都有**：出发前清单（全勾放行）+ 现场记录（JSONB 按模板）+ 附件 + 考勤 + 完成确认。

| | 特有的东西 |
|---|---|
| SM1 | 见到了谁（多选）、采集分包商进参建方表 |
| SM2 | **电工单向签字**（签纸拍照+留痕）；清单含 KNX/地暖条件项 |
| SM3 | **双向签字**（我方+电工）；**登记变更** |
| SM4 | 只带最新图纸；缺线拍照通知不动手 |

---

### 阶段 3：变更 Variation

**只在 SM3 产生，只留痕。**

- 类型：多加 / 减少 / 移位（移位在图上标，不记原坐标）
- 登记后**自动知会设计、采购、财务**三方 + 通知留痕
- **金额和工时在 SM3 都不碰**——物料自带时长，变更工时不单算
- 金额留到 **S4 由财务估价**填入，多退少补

> **变更 ≠ 整改**：整改是电工纠错（无成本），变更是设计变了（要结算）。

安装阶段现场又发现要改设计的，剩余项标 `to_variation` 并关联变更单——变更有了第二个入口。

---

### 阶段 4：采购

| 卡点 | 规则 |
|---|---|
| 下单 | 需 S2 已结清 |
| 发货 | 需工程预配完成 |

采购单上填 **物料保修月数**（各供应商不同），起算日 = **S2 结清日**。

---

### 阶段 5：安装调试

**一趟趟去**，`install_job` 一趟一条。要装什么记在项目级的 `install_item`。

| 剩余项状态 | 要求 |
|---|---|
| `pending` 还没做 | —— |
| `done` 做完了 | —— |
| `cancelled` 客户不装了 | **必须填原因** |
| `suspended` 缺货/场地/别的工种没完 | **必须填原因 + 卡在谁那** |
| `to_variation` 现场要改设计 | **必须关联变更单** |

**"清零"≠"全做完"**——后三种也算清零，但每次都留着名字和理由。
负责人点完工时看到的不是"还剩 3 项"，而是"3 项：1 项客户取消、2 项等空调队"。

---

### 阶段 6：交付

```
S4 结清 → 工程管理看流水账确认 ready → 派交付任务 → 上门 → 客户签收 → 完成
```

**S4 是硬卡，无后门**——钱没到，交付任务根本建不出来。
（讨论过"客户说先交付再付款"的死循环，公司立场是顶住，系统不给通融口子。）

**完成瞬间系统自动做三件事**：
1. 回写 `handover_at` —— 工程成本 / 运维成本的分界线
2. 状态转 `delivered`
3. **工程利润率定格落库**

---

### 阶段 7：长期运维

**支线跑法**（和主付款链不同）：
报价 → 财务发 Invoice → **运维可立即开工，不等付款** → 客户付款 → 结案

| | 免责维保 | 物料保修 |
|---|---|---|
| 起点 | **交付之日** | **S2 结清日** |
| 时长 | 0~12 个月（售前手填） | 各供应商不同（采购单填） |
| 覆盖 | 非人为故障：**人工+物料全免** | 只管物料 |

**期外收费**：物料没过保 → 只收人工；过保 → 人工 + 物料。财务报价。

**故障归因**上门后补填（去之前谁也不知道），**不填不许结案**——它决定收不收费。

**免责维保单开 $0 Invoice**：金额 0 照开发票，列明人工多少小时、换了什么件、免责覆盖、应付 $0。免费不等于白干。

## 三、贯穿全程的四条通用机制

这四条**不属于任何部门**，是全系统共用的底层能力。

### ① 考勤 work_log（所有活共用）

四类任务、每一趟上门，都走同一套：

- **围栏**：默认 100 米（按项目可调），圆心 = 项目坐标
- **入场**：定位优先，拍照兜底；拍照的**记录在案**，频繁拍照 → 标记追溯
- **离场**：现在（Web App）定时抽查位置，出围栏标"疑似离开"；将来（原生 App）后台持续定位自动离场——**字段现在就设计好，升级时结构不变**

### ② 路上时间 + 午餐（自动，人碰不到）

**traffic time slot = 上一站离场 → 下一站入场**，逐段编号 1、2、3…

全从打卡推导，**不用人填**——想少一段就得在打卡上动手脚，那条路已被围栏/拍照/留痕堵死。

**付薪按首尾**（澳洲规矩，路上不能克扣）：
```
当天工时 = 最后一次离场 − 第一次入场 − 午餐 30 分钟
```

**午餐自动扣不打卡**：首尾满 5 小时才扣；锚点 12:00 判定这顿饭算哪个项目。
> 不打卡是因为打卡能忘点/晚点/假点；必须扣是因为不扣的话，
> 准点上下班 8 小时的人也会被算成超时 30 分钟——**天天触发，门禁作废**。

**成本分摊**：路上成本**摊给下一站**（那趟车是为了去 B 才开的）；末站回程不摊。
**项目成本口径必须跟发薪口径一致**，否则利润率失真。

**Google 预估两版存死**：

| 显示 | 何时查 | 回答什么 |
|---|---|---|
| 计划预估 | 派活时，按**计划**出发时间 | 派活估时准不准 |
| 实际预估 | 收工后，按**实际**离场时间 | 那个时段本该开多久 |
| 真实耗时 | 打卡现算 | 实际开了多久 |

必须连"查询时用的出发时间"一起存死，否则拿今天的路况审昨天的人。
`avoid_tolls=true` 避过路费，**motorway 照走**（悉尼避 M2/M7 绕远，预估反失真）。
**只给工程管理看，不影响发薪；查不到就空，不进门禁。**

### ③ 每人每天上报（挂"人+日期"，不挂项目）

一人一天可跑几个项目，所以上报**横跨项目，每天一条**。

**两条超时线**（任一超 30 分钟即强制）：

| 线 | 拿什么比 | 抓的是 |
|---|---|---|
| 计划超时 | 在场总和 vs 当天派活计划总和 | **活比预想的难** |
| 工时超时 | 付薪时长 vs 标准 8 小时 | **加班了** |

分开是因为：堵车导致下班晚 → 工时超时（该付加班费，是事实）；活干不完 → 计划超时（要写原因，是问题）。

**五类问题**：研发 / 产品 / 市场 / 标准化 / 工程安排
不超时自愿填、超时不填不许提交、**SM 不报**（SM 不存在这 5 类问题）、**填写时间不计工时**。

### ④ 通知 notification + 留痕 handoff_log

全系统共用：变更知会、发 Invoice、SM4 缺线通知、催款……
覆盖内部（工作人员）+ 外部（客户/电工/Builder）。
**现阶段只做邮件单向**；短信、双向确认（收 yes 自动回）字段占位。
**系统只做"忠实告知 + 留痕"，不承诺对方执行。**

## 四、钱的全景

### 应收 / 实收拆两张

- **应收** `payment_milestone`：合同节点 S1~S4 **和** 维护单，共用一张表（`kind` 区分）
- **实收** `payment_receipt`：一笔款可分多次收，现金/走账混合

**GST 单列**：走账计（默认 10%），现金不计（默认 0），可手改。
⚠️ 现金/GST 涉及税务合规，系统只如实记录，报税以会计/税务顾问为准。

### 应收金额：发出即定格

- 发出前跟着签约价现算浮动（签约价 × 比例，S4 叠加变更）
- **一点"发出"就焊死**——客户手里那张纸和系统永远对得上
- 要改 → `invoice_ver` +1 重开新版

### 结清：系统算，财务点

| 项 | 谁决定 |
|---|---|
| 已收多少 / 还差多少 | 系统现算 |
| `partial`（收了不够） | **系统自动判** |
| `settled` | **只能财务点** |
| 足额 | 直接放行 |
| **不足额** | 放行，但**必须填原因**，**批准当时的差额定格落库** |

> 差额定格的理由：以后收到零头，现算值会变 0，当时的批准记录就糊掉了。

### 超期：只提示，不作废合同

| | 从哪算 | 谁看 |
|---|---|---|
| 本期超期 | 最后一版 Invoice 发出 | 催账 |
| **账龄** | **第一版发出** | 管理层，**改版抹不掉** |

标准 30 天。市场 + 财务介入催账，会再次催缴。

> 为什么要两个数：改版重发会让超期归零，而催账时改金额重发本是常规操作。账龄堵住这个口子。

### 拒付：财务手动标 → 项目级全面停服

不用等 30 天；停整个项目不是单张单；**任何新任务派不出去**；90 天后提醒停用服务器（市场发声明，人去执行）。

### 两个利润率

- **工程利润率** = (签约价+变更 − 采购成本 − 人工成本) ÷ 收入 → **交付当天定格落库**
- **长期利润率** = 工程利润 + Σ(运维收费 − 运维人力 − 运维物料) → **视图现算不落库**，单列"免责维保共免掉多少"

**成本归属**：**交付前所有维护单都算工程单**，交付后才算运维。建单时自动定格。

### 工资单

**每月 21 号定格，算的是上月 21 日 → 本月 20 日。**
⚠️ **必须按付薪时长（首尾 − 午餐）算，不能按 work_log 汇总**，否则每人每天少发路上工资。
薪酬敏感，权限阶段限可见范围。

## 四·五、工资：三种制度（v0.5–v0.6）

| | 月薪制 | 时薪制 | **外包** |
|---|---|---|---|
| 发薪 | 每月固定，**不发加班工资** | 付薪时长 × 时薪 | **固定日薪，去了就一天** |
| 周末/公共假日 | 整天算加班 | 整天算加班 | **没这个概念** |
| 加班 | 累计 → **倒休** | 按倍数付 | **没有加班** |
| 成本时薪 | 人工换算手填 | 就是发薪时薪 | **系统自动算 = 日薪 ÷ 参考时间** |

**外包也进 `eng_staff`**——考勤、工时、项目成本、流水账全套照用。
**时薪计算参考时间**不是"承诺工作多久"，是**算成本时薪的除数**（日薪 510 ÷ 10 小时 = 51）。

**日结当夜 0 点定格**，一人一天一条，定格即不可改；补录滚下月补发。
**没记录不扣钱，但挂起不发**——须负责人补录 + 填说明，同时永久进 KPI。
**月度周期 = 上月 21 日 → 本月 20 日**，21 日封账即发放，只做日结加总。

**加班判定**：平日超 8 小时的部分 + 周末整天 + **公共假日整天**（NSW 官方名单，一年更新一次）。

**入职前、离职后一律不生成日结。** 离职时系统算出未休倒休应结多少，**付不付由人定，不一致必须填原因**。

## 五、时间锚点总表（哪个日期决定什么）

| 锚点 | 决定 |
|---|---|
| **第六步签字** | 方案定版；解锁后续所有部门 |
| **S1 结清** | 工程可进场 |
| **SM3 完成** | 可发 S2 Invoice |
| **S2 结清** | 采购可下单 ／ **物料保修起算** |
| **SM4 完成** | 可发 S3 Invoice ／ 可派安装 |
| **S4 结清** | 可安排交付 |

| **Invoice 第一版发出** | 账龄起算 |
| **Invoice 最后一版发出** | 本期超期起算 |
| **拒付标记日** | 停服起算，90 天后提醒停服务器 |
| **每月 20 日** | 工资周期截止，21 日封账即发放 |
| **每天 0 点** | 前一天的日结工资定格，之后不可改 |

## 八、定格 vs 现算（这条分界最容易搞错）

### 定格落库（历史事实，以后不能变）

| 数据 | 何时定格 | 为什么 |
|---|---|---|
| 应收金额 | Invoice 发出时 | 客户手里那张纸不能变 |
| 结清差额 | 财务批准时 | 后来收到零头，现算会变 0，批准记录就糊了 |
| 账龄起点 | 第一版 Invoice 发出 | 改版不能抹掉 |
| 工程利润率 | 交付当天 | 交付后成本还在动，那天的数要留住 |
| 维护单成本归属 | 建单时 | 按当时是否已交付一刀切 |
| 是否免责维保覆盖 | 结案时 | —— |
| Google 路程预估 | 查询时（连出发时间一起） | 路况会变，不能拿今天审昨天 |
| 每日超时判定 | 提交时 | 后补工时不改历史判定 |
| **日结工资** | **当夜 0 点** | 含制度、发薪时薪、成本时薪、加班倍数 |
| 离职倒休应结 | 离职清算时 | —— |

### 现算不落库（会变的东西）

距今天数 ｜ 已收/还差 ｜ 超期天数与账龄 ｜ 路上时间 traffic slot ｜ 每人每天在场/首尾/付薪 ｜ 项目人工成本 ｜ 人工消耗% ｜ 工程流水账两个维度 ｜ 安装剩余统计 ｜ 两套维保到期 ｜ 长期利润率 ｜ 停服天数 ｜ **倒休余额** ｜ 外包实付与摊入差额"""
