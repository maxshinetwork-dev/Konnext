工程部门：设计思路与主要业务流

给工程负责人的一页说明——系统里工程管什么、现场流程怎么走、 哪些地方会被卡、做完一步谁会收到通知。看完欢迎直接提意见，规则都还能改。
面向 工程负责人 依据 项目决策记录 · 数据库契约 v0.33 整理日 2026-08-02

01系统怎么想工程这件事（三句话）

现场顺序 = 系统硬卡

SM 会议、出库、安装、交付的先后不是"建议"，是数据库里的门禁： 上一步没做完，下一步的按钮就是灰的，谁都按不动——包括老板。这样避免"先干了再补手续"。

留痕代替扯皮

签字、变更、完工原因、每天去了哪，全部当场记录。系统不裁判争议， 只保证事后能拿出"谁、何时、确认了什么"。

S 是钱，SM 是会

S1~S4 是四笔收款（定金10% / 物料款40% / 人工款40% / 尾款10%）； SM1~SM4 是四次现场会议。两套编号永不混用。 工程做完关键 SM，财务那边才收得了对应的钱。

02主业务流（工程视角，从进场到交付）

绿色=触发别的部门 · 红色=门禁原句（系统就是这么报错的，原样弹给操作人）

S1
前置 · 财务

定金 10% 结清

门禁定金没到 → 工程不能进场（SM1 排不了）
SM1
工程 · 现场会议

进场

与业主/Builder 首次现场碰面，采集缺的参建方联系人。出发前有检查清单—— 没勾完不能完成本次 SM（防止人到了现场缺东西）。

SM2
工程 · 现场会议

布线交流（交底给电工）

把 Finish 方案交底给电工，电工要签字。带线清单由售前录的"方案倾向"决定（有无 KNX、地暖）。 之后电工自行 Rough-in 布线，这段不占我们的人。

门禁SM1 未完成且未标记不适用，不能完成 SM2（顺序硬卡）
SM3
工程 · 现场会议 · ★关键节点

检查布线 · 双向签字 · 登记变更

验电工的活，双方签字。业主现场提的加减改动，只在这一步登记变更（拍照留痕，不谈钱）。

触发SM3 完成 → 财务收到待办「开 S2 物料款 Invoice」；变更同时知会设计 / 采购 / 财务
门禁SM3 未完成，不能发起 S2 物料款
S2
财务 · 收款

物料款 40% 结清

门禁S2 物料款未结清，采购不能下单 ／ 库管不能出库放货
出库
库管 → 工程

物料落到项目 · 预配 · 发货 · 封板

出库那一刻物料才算这个项目的（提货人短信确认）。工程做预配、发货到场，等封板。 领了没退的料以后会按出库价进 S4 结算——所以退料要及时。

SM4
工程 · 现场会议

封板核对出线

触发SM4 完成 → 财务可发起 S3 人工款（与电工补线解耦，互不等）
门禁SM4 未完成，不能发起 S3 人工款 ／ 安装调试必须在 SM4 之后
安装
工程 · 多趟任务

安装调试 → 整体完工

一趟一趟去，每趟记录做了哪些安装项。整体完工 = 剩余清零 + 负责人确认，两个都要—— 清零不等于全做完：取消/挂起/转变更都算清，但必须填原因。

门禁还有 N 项安装内容未清零(未做完/未取消/未挂起/未转变更)，不能确认安装完工
S4
财务 · 收款

尾款 10% + 可计费变更 + 未退料

SM3 登记的变更在这里跟客户结账（金额由财务外部算好填回）；移位属电工整改，不计费。

交付
工程管理 · 人肉确认

Handover 交付

系统不代替判断——工程管理看「工程流水账」确认条件齐了，但每一步留痕。

门禁S4 尾款未结清，不能安排交付（硬卡无后门）＋ 需已确认 ready ＋ 客户签收
触发交付完成瞬间：回写交付日 · 工程利润率定格 · 运维接管（免责维保起算）· 交付过程中签业主订阅

03工程的四类任务（顺序 = 现场先后）

① Site Meeting SM1~4

四次现场会议，顺序硬卡、出发前清单、该签字的必须签字。SM3/SM4 直接决定财务能不能收钱。

② 安装调试

SM4 之后一趟趟去。安装项清单化：做完打勾，做不了写原因（取消/挂起/转变更）。

③ 交付

S4 结清 + ready 确认 + 客户签收，三样齐才走。交付日定格利润率、开启免责维保。

④ 技术维护（配合运维）

只有已交付项目才受理维护。现场三样缺一不可：当着客户面确认故障归因、 写清当日服务内容、客户签字——否则任务点不了完成，人不能走。

04每天要做的两件小事

打卡：到场/离场打卡，项目坐标带考勤围栏（默认 100 米，负责人可按项目调）。 路上时间、午餐（自动扣 30 分钟，短工日不扣）系统自己算，不用填。

每日上报：一人一天一条，当天跨了几个项目就写几段。这是工资和项目成本的数据源。

没打卡没上报的那天：不扣钱（Fair Work 不允许惩罚性扣薪，且打卡失败常常不是人的错）， 但那天的工资挂起不发——需要负责人补录并填说明才放行，同时永久进 KPI。压力在管理层，不在工人。

05变更 Variation：只在 SM3、只留痕

类型计费规则
多加计费客户变更，进 S4 跟客户结账
减少计费负数冲减，同样进 S4
移位不计费电工装错位置属整改——照样登记留痕，但填金额系统直接拒

工程在 SM3 只管登记事实（拍照、描述、谁提的），金额和工时一律不碰—— 估价由财务＋库管外部算好填回。人工不单列（物料售卖价里已含安装人工）； 工时超支不挂客户，吃我们自己的工程利润率。S4 发票发出后变更就锁死，要改只能开 v2 重发。

06会卡住你的 / 你卡住别人的

方向门禁（系统原句）
卡工程门禁：定金(S1)未结清，不能安排 SM1 进场
门禁：出发前清单还有 N 项未勾选，不能完成本次 SM
门禁：S4 尾款未结清，不能安排交付
工程卡别人门禁：SM3 未完成，不能发起 S2 物料款 →（进而）采购不能下单、库管不能放货
门禁：SM4 未完成，不能发起 S3 人工款
门禁：项目尚未交付，不予受理维护单（运维那边建不了单）

按钮变灰时，鼠标悬停就能看到是哪条门禁卡的——不用猜、不用问。

08现在到哪一步了

上面这套规则已经全部写进数据库契约并通过验证（61 张表、134 条自动拦截测试、73 条数据自检全绿）—— 也就是说流程和门禁是定死的底座，不靠自觉。

界面目前做完了售前（已定稿）和财务（迭代中）； 工程的页面在财务之后按链路深化：SM1~4 → 出库 → 安装 → 交付。 所以现在正是提意见的最好时机——流程顺序、清单内容、签字环节、派工方式， 哪里和实际干活不一样，现在改成本最低。
