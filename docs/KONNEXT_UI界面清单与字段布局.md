## 零、一处对原方案的修正

你原话是「进入认证页面，在此选择对应的部门角色」。

**认证页不能让用户选部门角色**——那等于自己给自己配权限。按 v0.22 定的规则，部门归属由管理员在 `account_department` 里配好，系统一查就知道你是谁。

**正确流程：**

```
输手机号 → 收短信验证码 → 输码 → 系统按账号加载你的部门页标
```

**只有兼任多部门的人**（如老张：采购＋库管）登录后才会看到一个「以什么身份进入」的选择——那是**切视角**，不是选权限，两个身份他本来都有。单部门的人不出现这一步。

**第三级施工人员根本进不来这套后台**（`backend_access = false`）。他们用 App，是另一套界面，本文不含。

## 一、登录与认证

### 页面 A1 · 手机验证码登录

| 元素 | 说明 | 对应契约 |
|---|---|---|
| 手机号输入框 | E.164 格式，澳洲号自动补 `+61`、去掉前导 0 | `app_account.phone` |
| 「获取验证码」按钮 | 触发 Twilio 发送；60 秒内不可重复点 | 写 `auth_otp`（`purpose='login'`） |
| 验证码输入框 | 6 位数字 | `auth_otp.code_hash` 比对 |
| 有效期提示 | 「验证码 10 分钟内有效」 | `eng_setting.otp_valid_minutes` |
| 错误提示 | 号码不存在时**不要说"该号码未注册"**，统一提示「手机号或验证码不正确」——避免枚举员工号码 | —— |

**管理员额外一步（双重验证）**：手机验证通过后，再向 `email` 发一次码。两个都过才进。

### 页面 A2 · 身份视角选择（仅兼任者出现）

```
你的账号同时属于：  [ 采购 ]   [ 库管 ]
以哪个身份进入？                     （随时可在右上角切换）
```

选完写进会话（`SET app.account_id` 不变，视角只影响默认落地页与左栏默认展开项）。
**权限不受视角影响**——老张切到"采购"视角时，库管的页标仍然可见可用。

### 页面 A3 · 账号找回

- **管理员**：可自主找回（邮箱＋短信双验证）→ 写 `account_reset_log(action='self_recover')`
- **其他所有人**：页面只显示「请联系系统管理员重置」，**不提供自助入口**
- 管理员重置他人时必须填原因 → `account_reset_log.reason`

### 顶部导航（部门页标）

- **只显示你有权限的部门页标**，其余隐藏（不是灰掉——灰掉等于告诉别人有这个部门）
- **「决策页」固定在最后**，只有 tier 1 看得到
- 页标上可带角标显示该部门待办数（来自 `v_dept_workload`）

**页标可见性规则**（数据驱动，不要在前端写死）：

```sql
-- 一次查出当前账号该显示哪些页标
SELECT department FROM account_department WHERE account_id = :me;
-- tier=1 则显示全部 + 决策页
```

### 🔔 待办中心（全局，右上角）

这是整个系统的**推进引擎**，v0.23 建的 18 个交接点全汇到这里。

| 列 | 来源 |
|---|---|
| 事件 | `v_pending_handoff.event_label` |
| 谁交给我 | `from_dept_cn` |
| 我要做什么 | `action_needed` |
| 等了多久 | `waiting_hours` |
| SLA | `sla_hours`，**超期整行标红**（`overdue`） |
| 项目 | `project_code`，点击直达该项目 |
| 操作 | 「已知悉」按钮 → 写 `dept_handoff.acknowledged_at/by` |

**排序：超期在最上，其次按等待时长倒序。**

### 右栏统一三段式

所有业务页面都用同一个骨架，减少学习成本：

1. **筛选条** —— 项目 / 日期范围 / 状态 / 负责人
2. **列表或看板** —— 支持排序、导出
3. **详情抽屉（右侧滑出）或表单** —— 点行展开，不跳页

### 权限如何驱动界面

**按钮的显示与否不要在前端硬编码**，查这个视图：

```sql
SELECT table_name, can_write FROM v_my_permissions;
```

`can_write = false` → 该表相关的新增/编辑按钮**不显示**（不是点了才报错）。

**金额字段一律走遮罩视图**，查出来是 `NULL` 就显示 `— —`，不要显示 `0`：

| 看什么钱 | 用哪个视图 |
|---|---|
| 物料价格 | `v_material_masked` / `v_material_price` |
| 项目金额与利润率 | `v_project_masked` |
| 人员薪酬 | `v_staff_masked` |
| 应收实收 | `v_milestone_settlement` |

> ⚠️ **绝对不要让前端直接查基表**（`material`、`project`、`payment_milestone`…）。
> 基表没有列级遮罩，一查就把数字全带出来了。**只查视图。**

| 子页面 | 右栏放什么 | 主要对象 |
|---|---|---|
| **总览** | 我的项目卡片（状态/距今天数/下一步）、待跟进列表 | `v_project_overview` |
| **项目立项** | 建档表单 + 七步进度条 | `project` |

**项目立项表单字段布局**（分组，别做成一长条）：

```
【基本】     项目编号(自动 KX-2026-XXXX) · 项目名称
【地址】     街道 · Suburb · 州(8选1) · 坐标(自动生成，给地图与围栏)
【联系人】   业主一 / 业主二 / 关系人  ×(姓名·昵称·电话·邮箱·角色)
【佣金】     类型(百分比/固定) · 数值
【房屋】     用途(4选1) · 类型(9选1) · 施工阶段(9选+其他，必填)
【结构】     地下室/1层/2层/3层/4层及以上 ×(6种结构+无) · 屋顶(4选1)
【维保】     免责维保月数(0~12，默认3)   ← 签约时定死，之后影响交付后免费期
【进度】     七步时间戳（前六步售前填，第七步财务自动写）
【钱】       签约价   ｜ 定金(只读，财务写)
```

**必须做的两个交互：**
- **乐观锁**：进表单时记住 `version`，提交带上；冲突时提示「已被他人修改，请刷新」
- **第六步签字后**给出明确提示：「已通知财务开 S1 定金 Invoice」

### ③ 采购

| 子页面 | 右栏放什么 | 主要对象 |
|---|---|---|
| **总览** | 在途数量、待下单、红线预警、汇率新鲜度 | `v_material_stock` / `v_fx_current` |
| **物料主表** | ★核心表：列表 + 增/改/划掉/恢复/彻底删除 | `v_material_masked` |
| **汇率** | 当前汇率 + 历史（只增不改）+ 手工补录 | `fx_rate` / `v_fx_current` |
| **采购单** | 下单 → 明细 → 到货登记 | `purchase_order*` |
| **补货建议** | C1 低于红线清单，勾选后一键生成采购单 | `v_reorder_alert` |
| **调价历史** | 谁什么时候改了价/毛利率 | `v_material_price_history` |
| **RMA 索赔** | 需返供应商的坏货、在供应商处几天了 | `v_rma_supplier_track` / `v_rma_action` |

**物料主表列表列**

```
编号 │ 显示名(自动=物料名+规格) │ 品类 │ 协议 │ 供应商 │ 类 │ 红线 │ 库存 │ 在途 │ 采购价 │ 毛利率 │ 售卖价 │ 维保月 │ 操作
```

- **显示名一定用 `display_name`**（自动拼接）——白面板和黑面板的 `internal_name` 完全一样，只靠旁边小字区分会看串
- **划掉的行画删除线并排到最后**（`strikethrough`）
- 「彻底删除」按钮**只在 `can_hard_delete = true` 时出现**（从未产生流水）
- C2 的红线列显示 `—`，且**不可编辑**（严格不设红线）

**物料表单的三处提示**

- 利润率输入框旁注明：**毛利率口径，售卖价 = 成本 ÷ (1−利润率)**；填 ≥95% 直接拒
- 维保期旁注明：**厂商物料维保，与工程变更 Variation 无关**
- 划掉时**强制填原因**，且若仍有库存要弹提示「仍有存货 X 件，请安排出清或退货」

## 四、贯穿所有页面的六条规则

**① 报错信息原样透传。** 契约里的门禁提示都是完整中文句（「SM3 未完成，不能发起 S2 物料款」），直接显示给用户，不要包装成「操作失败，请重试」。

**② 按钮的可用性由数据决定，不写死。** 查 `v_my_permissions` 决定显示，查业务前置条件决定禁用，**并且鼠标悬停要说明为什么禁用**。

**③ 金额为 NULL 显示 `— —`，不显示 0。** 遮罩后是 NULL，显示 0 会被误读成"真的是零"。

**④ 定格的数据一律只读，并写明定格时间。** 日结工资、已发出的发票、盘点账面数、Google 预估、文档已发版本——这些改不了，界面上要说清楚是什么时候定的。

**⑤ 只查视图，不查基表。** 基表没有列级遮罩。

**⑥ 每个跨部门动作完成后，显示"已通知谁"。** 通知是这套系统推进流程的动力，静默发送等于没有。
